# Task: Accept explicit audit occurrence times

## Goal

Allow callers to provide the actual occurrence time for mutations that currently
stamp audit events with the wall-clock time.

## Context

Auditable mutations must accept explicit timezone-aware occurrence times so
replayed or imported operations can retain their original timestamps. Preserve
the current default timestamp behavior when callers omit the new optional input.
This task depends on TASK-API-004 for actionable timezone validation.

## Acceptance Criteria

- [ ] Add an optional, timezone-aware `occurred_at` input to governance vote,
  evaluation, and ruleset mutation operations that create audit events.
- [ ] Add an optional, timezone-aware `occurred_at` input to allocation schedule
  additions and cancellations that create audit events.
- [ ] Use the supplied instant for every audit event generated by the mutation,
  including approval events emitted during evaluation.
- [ ] Reject naive supplied timestamps with the actionable validation contract
  from TASK-API-004.
- [ ] Test exact audit timestamp preservation and confirm omitted timestamps
  retain the existing default behavior.
- [ ] Document the new public parameters and their timezone requirements.
